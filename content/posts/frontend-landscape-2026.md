## 框架还在吵，但战场已经挪走了

每隔一段时间就有人问"学 React 还是学 Vue"。2026 年这个问题已经不那么重要了，因为两个框架在往同一个方向收敛：**把能提前算的都提前算，把渲染往服务端推**。

React 19 这边，Server Components 从"可选优化"变成了默认姿势，React Compiler 把 `useMemo` / `useCallback` 这类手动优化接管了。以前为了性能写的一堆反直觉代码，现在编译器帮你做。

Vue 的动作更激进。3.5 重构了响应式系统，内存占用降了一大截，大数组操作性能提升明显；3.6 的 Vapor Mode 直接把虚拟 DOM 编译掉，生成原生 DOM 操作代码。这意味着 Vue 的性能逼近手写原生 JS，但你依旧用 Vue 的语法写。

所以现在真正需要花时间理解的不是"这个 API 怎么用"，而是：**哪些代码跑在服务端，哪些跑在客户端，中间那条边界上的数据怎么传**。hydration、streaming、partial prerender 这些概念比框架 API 更值钱，因为它们不会随版本过时。

## Rust 把构建工具链重写了一遍

这两年工程化领域最实在的变化，是构建工具集体换语言。

- Vite 6 稳定下来，成了新项目默认
- Rspack（Rust 版 Webpack）在存量项目的迁移上很能打
- Biome 用 Rust 重写了 ESLint + Prettier 的活，全项目检查从一分钟压到几秒
- Turbopack 跟着 Next.js 一起稳定

体感差距很大：以前一个中等项目冷启动构建两三分钟，现在十几秒。这件事的意义不只是"等得少了"，而是**AI 生成代码之后的迭代循环被压缩了**——你让 AI 改五个文件，五秒后就能看到结果，这个反馈速度决定了你敢不敢大胆地让 AI 动手。

## 端侧 AI 是前端手里的一张新牌

WebGPU 的浏览器覆盖率已经相当高了，加上 Transformers.js、WebLLM 这些框架，你现在可以在浏览器里直接跑模型。

我在本地试过的场景：上传一张图，浏览器本地识别内容，不传服务器。代码量不到两百行。这件事的意义在于，前端第一次有了"不需要后端就能提供 AI 能力"的可能——离线可用、隐私天然合规、响应即时。

当然边界也很清楚：浏览器里能跑的只有量化后的小模型，复杂推理还是得走服务端。但"小模型做预处理 + 大模型做深推理"这个组合，给前端留出了很大的设计空间。

## TypeScript 已经不是加分项

2026 年再讨论"要不要上 TS"有点过时了。中高级岗位基本默认要求，新项目默认 TS-first。

原因不只是类型安全。在 AI 大量生成代码的背景下，**类型定义成了人和 AI 之间的契约**——你把类型写清楚，AI 生成的代码准确率会明显提升；反过来，一个 `any` 满天飞的项目，AI 只会往里加更多 `any`。

## 我的判断

"前端已死"这个说法每隔两年就冒出来一次。这次不太一样的地方在于，被挤压的确实是"只写页面"的那部分工作。

一个更准确的描述是：岗位在往两头走。中间的 CRUD 业务前端在收缩，而复杂交互 / 性能优化 / 工程化 / 设计系统这些方向在涨。同时"前端 + Node 中间层 + AI 应用"的复合型岗位在变多。

所以我的学习顺序是：先把 TS 和框架原理打扎实，然后补 Node 和 AI 应用开发，最后才是追新框架的版本号。追版本号永远追不完，底层能力能用十年。
