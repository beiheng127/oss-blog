## 八股还是得背，但它只是及格线

浏览器渲染流程、事件循环、HTTP 缓存、TCP 三次握手——这些东西现在依然会考，只是形式变了。以前是"说一下强缓存和协商缓存的区别"，现在更可能是"我们的静态资源上线后用户看到的还是旧版本，你怎么排查"。

答案是一样的，但第二种问法要求你把知识挂在实际场景上。所以我的准备方法不是背条目，而是给每个知识点配一个"它会出什么故障"。

## 我整理的清单

### 网络与浏览器

- 从输入 URL 到页面显示，中间发生了什么（要能讲到 DNS、TCP、TLS、渲染、合成层）
- 强缓存 / 协商缓存的字段，以及 `Cache-Control: no-cache` 和 `no-store` 的区别
- 跨域：为什么简单请求不预检，预检请求带了哪些头
- HTTPS 握手过程，以及为什么需要证书链

### JavaScript 与 TypeScript

- 事件循环：宏任务微任务的执行顺序，`async/await` 到底在哪一步让出
- 闭包与作用域链，顺带准备"内存泄漏的常见原因"
- 原型链（现在问得少了，但被问到要说清）
- TypeScript 里 `type` 和 `interface` 的区别、泛型约束、`keyof` / `infer` 的实际用途

TS 现在是硬门槛，不是加分项。2026 年的数据很直白：新项目里 TypeScript 的使用率已经超过 80%，同一个岗位 title、同一家公司，会用 TS 比只会 JS 的薪资中位数高出一大截。

### 框架

- React：hooks 的闭包陷阱、`useEffect` 的依赖问题、为什么需要 `key`
- React Server Components：什么在服务端跑，什么在客户端跑，hydration 是什么
- Vue：响应式原理、`ref` 和 `reactive` 的取舍、Composition API 的组织方式
- 状态管理：什么时候需要 Pinia / Zustand，什么时候用 Context 就够了

### 工程化

- Vite 为什么快（ESM + 预构建），跟 Webpack 的构建模型差在哪
- 首屏优化指标：LCP、INP、CLS 分别衡量什么，怎么改善
- 代码分割、Tree Shaking 的前提条件
- CI 里应该跑哪些检查

### 现在的新增项

这一块是我去年完全没准备、今年必须补的：

- **AI 工具的使用经验**：你怎么把需求拆成 AI 能执行的任务？AI 生成的代码有 bug 你怎么定位？
- **流式渲染**：SSE 和 WebSocket 怎么选，断线重连怎么做，打字机效果怎么不卡
- **RAG 的基本链路**：文档解析 → 分块 → 向量化 → 检索 → 重排 → 拼接 prompt
- **端侧 AI**：WebGPU 能干什么，浏览器里跑模型的边界在哪

## 一个被低估的环节：反问

面试最后那句"你有什么想问我的"，我以前随便问两句就过去了。后来发现这是性价比最高的环节。

我现在固定问三个问题：

1. 这个岗位新人前三个月大概做什么？
2. 团队现在最头疼的技术问题是什么？
3. 你们日常怎么使用 AI 工具？

第三个问题尤其好用。一个重视 AI 的团队和一个把 AI 当作弊的团队，进去之后的两年是完全不同的。这个问题也在反向筛选——如果对方说"我们不让用"，那我大概不会去。

## 复盘比刷题重要

我给自己定的规矩是：每场面试结束当天，把被问到的题记下来，分成三类——

- 会但没答好（表达问题，练）
- 不会但应该会（知识漏洞，补）
- 不会也不该会（超纲，忽略）

第二类是重点。刷一百道题不如把二十个漏洞补上，因为漏洞是会重复出现的。
