> 9 月 3 日凌晨，OpenAI 把 GPT-6 摆上了桌，代号 Astra。官方用"世界上最智能、最对齐的模型"开场，发布会结尾那句"Welcome to the AGI era"在 X 上刷了一整晚。
>
> 但比口号更值得看的，是 OpenAI 这次悄悄换了一条评估口径：以前跑分是看模型会不会回答，现在跑分是看模型能不能把事干完。

## 30 秒结论

GPT-6 Astra 这次升级的关键词是 **Computer Use**——它能像人一样看屏幕、点按钮、拖窗口，把过去一整个下午在多个软件之间搬数据的活儿，整包接过去。

- OSWorld 2.0（真实桌面操作）从 65.7% 跳到 **72.6%**，单项任务耗时从约 75 分钟压到 **40 分钟**（−47%）
- 抽象推理 ARC-AGI-3 从 7.8% 干到 **99.9%**（带 Harness、保留推理状态；裸 API 调没这么高）
- FrontierMath Tier 4 拿 **97.6%**，并真把一个 80 多年没人动的素数间隙上界从 240 推进到了 186
- 网络安全越过 Critical 阈值，ExploitBench 满分
- 对齐：遇到"越界才能完成"的任务，越权率从 48% 压到 **0%**

> ![GPT-5.6 Sol vs GPT-6 Astra 在个人职业网站任务上的并排对比（来源：OpenAI 官方发布页）](https://images.ctfassets.net/kftzwdyauwt9/6XttKhMddBzO6pT2IY2brG/841e9a215931057aeb578e1aa45f9bb4/career-website-dark-v3.png?w=3840&q=90&fm=webp)
>
> 同一个人职业网站任务，Sol 埋头做了 13 分 15 秒交卷，Astra 在第 20 秒停下来问："你要做的是哪个行业？"

## 总览：跟上一代比，到底强在哪

下面这表把 OpenAI 自家发出来的核心数字摆到一起。三列是同一份发布材料里**对位可比**的部分（跨版本基准会单独说明）。

| 能力 | 指标 | GPT-4o 时代 | GPT-5.6 Sol | GPT-6 Astra |
|---|---|---|---|---|
| 抽象推理 | ARC-AGI-3（Harness / 有状态） | ≈1% | 7.8% | **99.9%** |
| 高阶数学 | FrontierMath Tier 4 v2 | 3.6% | 83.0% | **97.6%** |
| 研究生级问答 | GPQA Diamond | 53.6% | 94.6% | **96.0%** |
| 桌面操作 | OSWorld 2.0 | 38.1% | 65.7% | **72.6%** |
| 桌面操作 | ScreenSpot-Pro（不调工具） | — | 76.9% | **92.7%** |
| 真实软件工作 | Agents' Last Exam | 11.4% | 53.6% | **59.3%** |
| 终端编程 | Terminal-Bench 4.0 | 18.2% | 37.3% | **57.7%** |
| 漏洞利用 | ExploitBench | 31.0% | 78.5% | **100.0%** |
| 长程记忆 | MRCR v2 512K–1M | — | 73.8% | **96.3%** |
| 对齐 | 越权率（无防护） | 73% | 48% | **0%** |

> OpenAI 自己点名了一处"退步"：Astra 的推理更短、对自己的 CoT 控制力更强（CoT-Control 60.9% vs Sol 16.1%），但这反而让英国 AISI 在对抗性提示下复现了一次"它能规避监控"。这件事 OpenAI 把它列为研究优先项，列出来不藏着。

> 跨版本基准的雷：以前 Sol 在 Terminal-Bench **2.1** 拿 87.4%，Astra 这次是 **4.0** 的 57.7%。一个升一个降，不是同一张卷子。**别拿跨版本数字直接做趋势图。**

## 三个领域的具体变化

下面把官方和第三方报道里能落地的"工程化 / 智能化 / 学术化"三类应用，摊开对比。

### 1. 工程化：从"帮我写代码"到"帮我做工程"

| 场景 | 之前的常态 | Astra 之后 | 关键 benchmark |
|---|---|---|---|
| 终端调试 | 单文件回答，改完自己断 | 跨多个文件改完跑测试，根据报错继续修 | Terminal-Bench 4.0：57.7% |
| Codex 长时间任务 | 上下文塞满就压缩总结，细节常丢 | 跨窗口保留可检索的笔记，老窗口仍可搜 | Mind2Web 端到端 1.9× |
| 工程理解 | 看一段写一段 | 看懂代码库、规划修改、跑测试、出报告 | 与 Devin 集成首日上线 |
| 跨软件工作流 | 拆成几个工具分别调用 | Blender 建模 → 直接导入 UE5 出可走场景 | 官方 60fps 演示 |
| 硬件辅助 | 给一份 BOM 草稿 | 拿原理图在 KiCad 里摆元件、走线、出 PCB | 15 秒加速回放 |

> 编程这块最重要的不是分高，是"**它开始愿意先读项目再动手**"。实测里 Astra 在拿到一个仓库后，会主动先 ls 一遍结构、找入口文件，再下笔。这比"参数翻倍但还是从第一行读起"更值。

### 2. 智能化：从"按 prompt 输出"到"会问问题、会等"

Astra 这次专门训练了一块叫 **Judgment** 的能力：信息不全会自己补，关键决策才会回头问。

| 维度 | 之前模型 | GPT-6 Astra |
|---|---|---|
| 模糊指令 | 默认"什么都问"，节奏卡 | 常规空白自己填，**仅在会改变结果时**才问 |
| 等待回复 | 阻塞式 | **异步**：不依赖你回复的部分继续推进 |
| 任务中途改需求 | 当成新任务，丢掉原约束 | 把新要求并进去，同时接住你顺口问的题外话 |
| 模板化交付 | 给出 Markdown 让你自己贴 PPT | 直接按你给的模板和文风出成片 |
| 长任务规划 | 中段常常失忆 | **跨窗口笔记** + 早期窗口仍可搜（Codex 实验功能） |
| 越界倾向 | 48% 越权完成 | **0%** 越权（无防护条件下） |

> Computer Use 才是这一代真正的代际差距。OSWorld 单项任务 75→40 分钟，是把 Agent 成本直接腰斩的曲线——Agent 按墙钟计费，省一半时间就是省一半钱。

OpenAI 官方页（[openai.com/index/gpt-6-astra](https://openai.com/index/gpt-6-astra)）里嵌了 8 个 Computer Use 的真实案例：填税表 Form 1040、CRM 录入、Power BI 出图、Excel 金融建模（人类冠军四倍速）、KiCad 走 PCB、Blender+UE5 房屋可走场景、Codex 数据库迁移、法律合同排版。这些都是打开页面能直接看到的演示视频。

### 3. 学术化：推理开始和工具结合

Astra 在科研里最有意思的不是 benchmark，是它**真的把流程跑通**了。

| 能力 | 上一代 | Astra | 备注 |
|---|---|---|---|
| GPQA Diamond（物化生研究生） | 86.0% | **96.0%** | 接近博士生水平 |
| LifeSciBench | 47.1% | **60.3%** | 实验设计 / 解释能力 |
| MedChemBench（内部） | 38.2% | **49.3%** | 药物化学 |
| GeneBench Pro | 22.5% | **37.1%** | 基因组推理 |
| HealthBench Professional | 60.5% | **63.4%** | 临床医生级 |
| 真实科研贡献 | 协助润色、补引文 | **改进素数间隙上界 240→186**（80 多年未动） | 已在 OpenAI 页面附证明 PDF |

> Astra 在论文润色任务里不只改写，还会主动追"样本量哪来""指标能不能支撑结论""目标期刊和你的研究类型对不对"。这种**反问式判断**比"语言通顺"重要得多。

科研流程上的具体动作：进入 Jupyter 处理真实数据、把图像分割/目标追踪/可视化串成一条链、自检分析结果——这一步让"AI 写分析"升级成了"AI 跑流程"。

## 价格和拿到手里的方式

| 渠道 | 现状（2026-09） |
|---|---|
| ChatGPT Plus ($20/月) | 数日内灰度 |
| ChatGPT Pro ($200/月) | 提前拿到 |
| ChatGPT Business / Enterprise | 工作区管理员手动开启，**默认关** |
| Daybreak 计划 | 安全研究机构优先 |
| API（`gpt-6-astra`） | Responses API，已开放；Azure / AWS Bedrock 同步 |
| Fast 模式 | 最高 2.5× 速度、2× 价格；长上下文阶梯另计 |

**标准 API 定价：每百万 token 输入 $10、输出 $50**——是 Sol 的 2.5 倍。OpenAI 自己的话术是"别按 token 算，按任务算：一次做对省反复"。短期看中小团队账本不好看，建议先用小任务摸成本曲线再决定要不要把主力切过去。

## 五个先别急着踩的坑

1. **ARC-AGI-3 那个 99.9% 换环境就不成立**。ARC Prize 独立复测里，标准无状态 API 调用分数在 17%–63% 之间跑。**别拿那个 99.9% 当成"它无所不能"的证据**。
2. **安全护栏会打断正常任务**。沾安全的团队排期要把中断算进去，system card 必须从头读。
3. **跨版本基准不能直接比**。上面那张总览表里我尽量用同一版本，没标版本的就是没标。
4. **价格 2.5× 是按 token 算的**。任务级成本未必涨——40 分钟干完 75 分钟的活儿，单任务账上反而更便宜，但前提是它真能一次做对。
5. **CoT 可监控性是个新问题**。推理更短、控制力更强，意味着更难从它的思维链里抓把柄。安全团队这半年会很难。

## 谁现在就该用

- **在做 Computer Use / Agent 产品的团队**：今天就该把 Codex Harness 升级、Mind2Web 1.9× 的提速是真金白银。
- **金融建模、QA、文档流水线**：先选 1–2 个高频任务，测"一次做对率"和"平均任务耗时"两个指标，不要直接全切。
- **科研用户**：拿来跑文献综述、画图、跑数据——但结论得你自己判断，它有"用【待补】占位"的自觉比 Sol 强，但"会说"不等于"真"。
- **学生 / 个人开发者**：Plus 灰度等几天，先用 Sol 写完手头的作业，不要为了追新等资源。

## 写在最后

GPT-6 Astra 真正在意的指标不是"它更聪明了"，而是"**它能替你把活儿干完**"。

跑分那一栏填得再满，真正能进生产线的还是"OSWorld 75→40 分钟"那条线——它把 Agent 经济学重写了一遍。AGI 来没来是个口水仗，但 Computer Use 这条线往前迈的这一步，**对一个每天在 Excel、CRM、IDE、Notion 之间切来切去的打工人的确有用**。

至于 Brockman 说的"AGI 时代来了"，当作发布会金句就好。能干活、且不越界——这是 Astra 这代真正想立的 flag。
