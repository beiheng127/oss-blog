端侧 AI：前端手里的一张新牌

浏览器里能跑模型之后，前端第一次有了"不依赖后端也能提供 AI 能力"的可能。

李亚恒

07 9月 2026 • 阅读时间 3 分钟
分享
前端 AI

变化是从哪里开始的

真正的分水岭是 WebGPU。浏览器终于能直接调用 GPU 做通用计算，性能比纯 JS 快一到两个数量级。配合 Transformers.js、ONNX Runtime Web、WebLLM 这些运行时，在浏览器里跑一个量化后的小模型已经不是 demo 了。

在此之前，前端在 AI 产品里的角色很固定：调接口、渲染结果。模型在云端，前端是展示层。现在这条边界松动了。

端侧能干什么

我把它分成四类场景：

隐私敏感的处理。用户上传一份合同、一张体检报告，你需要在本地提取信息。走云端意味着数据要出境、要过合规、要签数据处理协议。放本地跑，这些麻烦全没了。

离线可用。飞机上、地铁里、内网环境。本地模型不依赖网络，这是云端方案给不了的。

高频低延迟的小任务。文本纠错、简单分类、关键词提取、格式规整——这类任务用小模型足够，本地跑延迟能做到几十毫秒，比网络往返还快。

云端推理的预处理。本地小模型先做一遍摘要或者意图识别，再把压缩后的结果交给大模型。这一步能省下大量 Token。

不能干什么

边界同样清楚，别高估它：

  • 复杂推理做不了。浏览器里跑的是量化后的 1B—3B 量级模型，让它做多步推理基本是在为难它
  • 首次加载是硬伤。模型文件几十 MB 到几百 MB，第一次打开要下载。虽然有 Cache API 可以持久化，但用户体验上必须有明确的进度提示
  • 设备差异大。有独显的笔记本和五年前的手机，性能差十倍不止。必须做能力检测和降级
  • 内存占用。移动端浏览器给单个标签的内存有限，模型一加载，页面可能直接被回收

一个最小实现

用 Transformers.js 做文本向量化，代码大概这样：

import { pipeline } from '@xenova/transformers';

const extractor = await pipeline(
  'feature-extraction',
  'Xenova/all-MiniLM-L6-v2',
  { progress_callback: p => updateProgress(p) }
);

const output = await extractor('这是一段待向量化的文本', {
  pooling: 'mean',
  normalize: true
});

progress_callback 一定要接，否则用户面对的是一个白屏和几百兆的静默下载。

我的判断

端侧 AI 不会取代云端推理，但它改变了产品的设计空间。

以前做 AI 功能，第一反应是"接哪个 API、Token 多少钱"。现在可以多一个选项：这件事能不能放在用户设备上做？如果能，成本为零、隐私天然合规、延迟更低。

对前端来说，这是个好消息。行业里"只写页面的前端"在被挤压，而"能做 AI 产品的前端"在涨价。会 WebGPU、懂模型量化、能设计 AI 交互的人，现在还很少。

稀缺本身就是机会。
